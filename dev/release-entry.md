## 83.2.6 ({{STAMP}}): The right artist, and a check that runs on its own

- **WHAT THE OWNER SAID.** *"fix the looking for a new release - it should do that in the background then notify you about it ... if the artist name is SUKHA it should just get me songs from the dude named SUKHA in the right genre, it should not add anything like SUKHA MANN."*
- **WHY SUKHA MANN WAS IN THE LIST.** `window.__scSameArtistName` accepted a whole-word PREFIX on purpose: a pinned "Sukha" was treated as the same artist as "Sukha Mann", "Sukha Dhaliwal" and anyone else whose name starts that way. Every catalogue pass, the artist-id resolution and the MusicBrainz and Wikidata credit tests use that one function, so a single rule filed other acts' songs under a pinned artist.
- **WHY THE CHECK DID NOT RUN ON ITS OWN.** `scPinnedAutoCheck` wrote its six-hour stamp BEFORE running, then returned at once when the pin list had not loaded yet. A launch that beat the library therefore wrote "checked just now", and every timer for the next six hours read it and did nothing.
- **THE FIX.** Names are compared exactly now - case, punctuation and a leading "The" still match, words added to the name do not. The pinned artist is resolved once to the Apple artist ids carrying exactly that name, narrowed by the genre of the songs already in the library, and kept for a fortnight; every result from every source is filtered by that id, so a namesake in another genre stays out. The stamp is written after a run that actually happened, the floor is two hours instead of six, and a tick runs every twenty minutes while the app is open, including in the background, announcing on the phone's shade through the same path as before.
- **THE OLD LIST.** Rows an earlier build stored carry no artist id to test, so the snapshot is thrown away once and refilled - quietly, every row already marked announced, so the phone does not read out a dozen songs that were never this artist's.
- **CHECKS.** `dev/patch-8326.py --check` exits 1 before the payload and 0 after it, and a second run is a no-op. The diff is the name test, the identity and the id filter, the auto-check clock, the one quiet rebuild, `APP_VERSION` and a four-line changelog entry, plus the service-worker cache name. All seven script blocks of the patched page parse. The matcher and the identity were extracted from the built page and run under Node: "Sukha Mann" against "Sukha" is refused; "SUKHA" against "sukha" and "The Weeknd" against "Weeknd" are accepted; a collab credit still finds the artist inside it; a row from the Sukha Mann id and one from a rock namesake are both refused while the Punjabi one passes; and the second call reads the cache instead of the network. Rebuilt bundles: {{ROOT}} bytes on the full channel, {{PLAY}} on the store build.
- **NOT CLAIMED.** No phone has pinned Sukha. What is proven is what the page does with catalogue rows, in Node. The notification itself is the existing `scReleaseAlert` path, and nothing in that path changed - what changed is when and how often the check that feeds it runs.
